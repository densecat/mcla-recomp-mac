# Patches to the ReXGlue SDK

Apply to ReXGlue v0.10.0 (`f5337cdc947ff6d4c4196737e2c807a48f2a1fc2`), from the SDK checkout:

```
git apply ../../patches/rexglue-v0.10.0-mcla.patch
git apply ../../patches/rexglue-v0.10.0-metal.patch
git -C thirdparty/FFmpeg apply ../../../../patches/rexglue-ffmpeg-ps5-config.patch
```

They were separate files at first; they are combined now because several touch the same build files and would not apply independently.

## rexglue-v0.10.0-mcla.patch

| Change | Files | Affects |
|---|---|---|
| Vblank timer resync: the guest tick count can step backwards, which made an unsigned difference wrap and fire vblank interrupts without end | `src/graphics/graphics_system.cpp` | all platforms |
| Per-frame counters kept in Release builds, and their CSV path taken from `REX_PERF_LOG_CSV` (the `perf_log_csv` option is declared but never read) | `CMakeLists.txt`, `src/core/CMakeLists.txt`, `src/system/CMakeLists.txt`, `src/core/perf/counter.cpp` | all platforms |
| The Vulkan backend fills the draw, vertex, stall and pipeline-cache counters, which only D3D12 incremented, so they read 0 on macOS; texture-cache hits and misses are counted in the shared texture cache when D3D12 is not built (D3D12 keeps counting its own descriptor lookups). New columns, appended so existing ones keep their positions: `render_passes_begun`, `submissions`, `fence_wait_us`, `upload_bytes`, `descriptor_set_writes`, `pipeline_compiles`; then render-pass ends by reason (`pass_end_barrier_upload`, `_barrier_texture`, `_rt_change`, `_transfer`, `_resolve`, `_memexport`, `_query`, `_swap`, `_other`) and shared-memory bytes selected for upload by cause (`upload_planned_first_bytes`, `_fault_bytes`, `_explicit_bytes`, `_other_bytes`, `_hot_bytes`) | `include/rex/perf/counter.h`, `src/core/perf/counter.cpp`, `src/graphics/shared_memory.cpp`, `include/rex/graphics/vulkan/command_processor.h`, `src/graphics/vulkan/command_processor.cpp`, `src/graphics/vulkan/pipeline_cache.cpp`, `src/graphics/vulkan/shared_memory.cpp`, `src/graphics/vulkan/texture_cache.cpp`, `src/graphics/vulkan/render_target_cache.cpp`, `src/graphics/vulkan/primitive_processor.cpp`, `src/graphics/pipeline/texture/cache.cpp` | Vulkan builds with counters on, except PS5 (diagnostics only); CSV gains columns everywhere |
| Debug-only register lookup removed from every GPU register write in Release builds | `src/graphics/command_processor.cpp` | all platforms |
| Unit tests build on macOS: they link xxHash (`hash_test` includes it through `rex/hash.h`, which the runtime libraries link only privately), compare file times without printing them (Apple's libc++ counts them in `__int128`, which Catch2 cannot print), and the depfile test's expected strings keep their backslashes (`"has\ space"` was an invalid escape that dropped it) | `tests/unit/CMakeLists.txt`, `tests/unit/codegen/codegen_writer_test.cpp`, `tests/unit/codegen/output_stamp_test.cpp` | test builds only, all platforms |
| Guest memory barriers: `sync`, `lwsync`, `eieio` and `ptesync` emit `REX_SYNC()` and friends, `dmb ish` on arm64 (whose loads and stores can be reordered, unlike x86's) and nothing on x86; `isync` emits `dmb ish; isb` on arm64 (the guest's branch before it may be folded away by the compiler) and a compiler barrier elsewhere instead of throwing as unimplemented; the `lwarx` reservation load is volatile. `REX_GUEST_BARRIERS=0` turns the barriers off for measurement | `src/codegen/builders/system.cpp`, `src/codegen/builders/helpers.h`, `src/codegen/builders.h`, `src/codegen/instruction_dispatch.cpp`, `resources/templates/codegen/pch_h.inja`, `resources/templates/test/ppc_config_h.inja` | barriers arm64 only; `isync` and the volatile load all platforms |
| `mtfsf` set the FPSCR fields in reverse order, so `mtfsf 0x01` (rounding mode) changed nothing and `mtfsf 0x80` overwrote it | `src/codegen/builders/system.cpp` | all platforms |
| Rounding mode read back by `mffs` used the x86 encoding, swapping up and down on arm64; the arm64 FPCR access takes a 64-bit operand and orders against memory | `include/rex/platform/fpscr.h`, `include/rex/ppc/context.h` | arm64 |
| A fault no handler claims goes on to the handler installed before ours (guest SEH; if that handler returns, ours stays installed) or else takes the default action, instead of re-faulting forever | `src/core/exception_handler_posix.cpp` | macOS only |
| Thread priorities map onto Darwin's `SCHED_OTHER` range (the raw values were outside the `SCHED_FIFO` range) and read back as the value set; creation flags pass `ThreadPriority` values | `src/core/threading_posix.cpp`, `src/system/xthread.cpp`, `include/rex/system/xthread.h` | macOS only |
| Hot-page deadlines: 0 means none, so a page is no longer read as hot once the host has been up for 2^31 ms (about 24.9 days, even with the feature off); expired deadlines are cleared | `include/rex/graphics/shared_memory.h`, `src/graphics/shared_memory.cpp` | all platforms |
| Write-watch on hosts with pages larger than the guest's (16 KiB on Apple Silicon and PS5): whether to watch a host page, and what access to restore, is judged from every 4 KiB guest page it holds, not only the first, so CPU writes to a writable page behind a read-only one are no longer missed by the GPU cache | `include/rex/system/xmemory.h`, `src/system/xmemory.cpp` | 16 KiB-page hosts (unchanged with 4 KiB pages) |
| PPC instruction tests: x86 flags only on x86, `REXGLUE_PPC_PREBUILT_DIR` to use test binaries assembled elsewhere (the bundled PowerPC binutils run only on Linux and Windows), and new `mtfsf`, rounding and barrier tests | `tests/ppc/CMakeLists.txt`, `cmake/ppc_test_pipeline.cmake`, `tests/ppc/asm/instr_mtfsf.s`, `tests/ppc/asm/instr_fadd_rounding.s`, `tests/ppc/asm/instr_sync.s` | test builds only |
| PS5 platform: everything else. Platform detection, libc and libc++ differences, anonymous shared memory with a shared-object address reservation at a kernel-chosen base, 16 KiB host pages, signals without realtime signals, no X11/Wayland/RenderDoc, static runtime and GPU libraries, no desktop install rules | the remaining files | PS5 only, behind `REX_PLATFORM_PS5` or `if(PS5)` |

Details of the PS5 changes are in `docs/ps5-port-plan.md`.

## rexglue-v0.10.0-metal.patch

A native Metal GPU backend for macOS, applied after `rexglue-v0.10.0-mcla.patch`. It is opt-in: `--mcla_gpu_backend=metal` selects it, and `any` still picks Vulkan. Work in progress; see `docs/known-issues.md`.

| Change | Files | Affects |
|---|---|---|
| `REXGLUE_USE_METAL` (on for Apple, forced off elsewhere) and `REX_HAS_METAL`; metal-cpp fetched at commit `27c4382b7151d55a51692cdcb27aaa98752240de` | `CMakeLists.txt`, `cmake/rexglue_metal.cmake`, `src/core/CMakeLists.txt`, `src/system/CMakeLists.txt`, `src/ui/CMakeLists.txt`, `src/graphics/CMakeLists.txt` | macOS builds |
| Milestone 1: Metal provider, presenter (CAMetalLayer) and immediate drawer in the runtime; a `metal` choice in the GPU plugin whose command processor counts guest draws and copies without rendering them and presents a clear color | `include/rex/ui/metal/*`, `src/ui/metal/*`, `include/rex/graphics/metal/*`, `src/graphics/metal/*`, `src/graphics/plugin_main.cpp` | macOS, only when the `metal` backend is chosen |
| Milestone 2a: guest draws are encoded for real. Guest shaders go through the SPIR-V translator and SPIRV-Cross to MSL, compiled at run time; render pipeline and depth-stencil states are cached. Guest memory is a 512 MiB shared-storage buffer updated with CPU copies instead of blit passes; a page still used by the command buffer being recorded splits the submission, one used by unfinished GPU work is waited for. Still missing: textures (placeholders), guest render targets (one scratch target), resolves, presentation of guest frames. New counters `metal_draws_encoded`, `metal_msl_compile_failures`, `metal_pipelines_created`, `metal_split_for_upload`, `metal_upload_wait_us`, `metal_placeholder_texture_draws` | `include/rex/graphics/metal/*`, `src/graphics/metal/*`, `src/graphics/CMakeLists.txt`, `include/rex/perf/counter.h`, `src/core/perf/counter.cpp` | macOS, only when the `metal` backend is chosen (counters: CSV columns everywhere) |
| Milestone 2b (in progress): guest render targets in the host render-target path, with Metal formats chosen as on MoltenVK and D24S8/D24FS8 stored as Depth32Float_Stencil8; render passes begin and end only when bound targets change; same-format colour and depth EDRAM transfers; `metal_debug_present_last_rt` (default on until resolves exist) shows the last guest colour target at each swap. Not yet visually verified. Counters `metal_rt_transfers_skipped`, `metal_render_targets_created` | `include/rex/graphics/metal/*`, `src/graphics/metal/*`, `include/rex/perf/counter.h`, `src/core/perf/counter.cpp` | macOS, only when the `metal` backend is chosen |
| Milestone 3: texture cache. Guest textures are untiled and converted on the GPU by the SDK's texture-load compute shaders, translated from their SPIR-V to MSL at run time; BC formats are used natively when the device supports them, with a decompression path otherwise; samplers follow the guest fetch constants. Host-depth snapshots for render-target preservation are kept per target instead of recreated (this was the per-frame render-target churn). Untextured fallbacks are mid-grey. `metal_dump_frame`, `metal_dump_every` and `metal_dump_path` write the presented guest output as PNG | `include/rex/graphics/metal/*`, `src/graphics/metal/*`, `include/rex/perf/counter.h`, `src/core/perf/counter.cpp` | macOS, only when the `metal` backend is chosen |
| Milestone 4 (in progress): resolves run the SDK's resolve compute shaders (SPIR-V translated to MSL) into the shared-memory buffer and mark the range written by the GPU; EDRAM dump/load shaders come from the Vulkan backend's SPIR-V generators; the swap presents the guest frontbuffer through the texture cache. 1x only: scaled resolves are rejected and counted in `metal_resolves_unsupported`. Known issue: the title screen shows only sky haze and bloom, the scene and 2D overlay are missing | `include/rex/graphics/metal/*`, `src/graphics/metal/*`, `include/rex/perf/counter.h`, `src/core/perf/counter.cpp` | macOS, only when the `metal` backend is chosen |

## rexglue-ffmpeg-ps5-config.patch

FFmpeg selects a configuration header per platform. This adds `config_ps5_x86_64.h`, generated from the Linux x86-64 one with `HAVE_MALLOC_H`, `CONFIG_ICONV`, `HAVE_MEMALIGN`, `HAVE_SCHED_GETAFFINITY` and `HAVE_LINUX_PERF_EVENT_H` turned off, and selects it for `__PROSPERO__`.
